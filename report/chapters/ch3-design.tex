\chapter{System Design \& Architecture}

\section{Object-Oriented Design Principles Applied}
The program applies four principles \cite{ref1}. Each one has an example from
the code.

\textbf{Encapsulation.} The fields of a class are private. Other classes use
getter methods, so only the class itself can change its data.

\begin{lstlisting}[style=java]
public class Hub {
    // Private field: only this class can change it
    private String name;

    public String getName() {
        return name;
    }
}
\end{lstlisting}

\textbf{Abstraction.} \texttt{Parcel} is an abstract class. It declares the
method \texttt{calculateTotalFee()} without a body. Each speed class must
write its own version.

\begin{lstlisting}[style=java]
public abstract class Parcel {
    // No body here. Each speed class must write its own version
    public abstract double calculateTotalFee();
}
\end{lstlisting}

\textbf{Inheritance.} \texttt{StandardParcel}, \texttt{ExpressParcel}, and
\texttt{OvernightParcel} extend \texttt{Parcel}. They reuse its fields and
methods and add only what is different.

\begin{lstlisting}[style=java]
public class ExpressParcel extends Parcel {
    public ExpressParcel(String trackingId) {
        super(trackingId, "Express", 2); // calls the Parcel constructor
    }
}
\end{lstlisting}

\textbf{Polymorphism.} The method \texttt{getHistoryText()} in \texttt{Parcel}
calls \texttt{calculateTotalFee()}. At run time, Java runs the version of the
real speed class. \texttt{ParcelFactory} returns a \texttt{Parcel} that is
really a \texttt{StandardParcel}, an \texttt{ExpressParcel}, or an
\texttt{OvernightParcel}.

\begin{lstlisting}[style=java]
// in Parcel: runs the code of the real speed class
text = text + "Total fee: " + calculateTotalFee() + "\n";

// in ParcelFactory: the return type is Parcel
if (speed.equals("Express")) {
    return new ExpressParcel(id);
}
\end{lstlisting}

\section{Data Structures \& File Storage Design}
The program keeps the parcels in an \texttt{ArrayList} \cite{ref1}, the hubs in an array,
and the history of each parcel in an \texttt{ArrayList} of milestones.

The program uses two text files, one line per record, with commas between the
values:

\begin{itemize}
\item \texttt{manifest.txt}: tracking ID, speed, current hub.
\item \texttt{status-log.txt}: tracking ID, hub, time.
\end{itemize}

The program replaces the manifest on every save. It only adds lines to the end
of the status log.
